# vampn (сторож и управление VPN)

Один скрипт `vampn`, который на homeserv лежит в `/usr/local/sbin/vampn`; сторож запускается таймером systemd раз в минуту (`vampn check`).
Здесь хранится его копия. Скрипт с ролями (homeserv, VPN-сервер, аварийный Бостон) определяет роль по конфигам AmneziaWG.

## Как сторож решает, что туннель мёртв
Связь есть, если рукопожатие моложе 45 с **или** sshd VPS отвечает через туннель (TCP 22 на 10.77.0.1 через интерфейс `vampn`;
на VPS этот порт открыт файрволом только для `awg0` и только с адреса homeserv 10.77.0.3).

| минут без связи | действие |
|---|---|
| 2 | перезагрузка VPS через API Timeweb (не чаще раза в 30 мин) |
| 3 | аварийный канал (Бостон) включается сам, аварийные ключи уходят на почту (одна попытка на аварию) |
| 5 | смена IPv4 (только при статусе сервера `on` в Timeweb) |

## Смена IP (`vampn rotate [--force]`)
0. Менять IP можно только при статусе `on` в Timeweb (и ручная смена тоже): пока сервер выключен или перезагружается, смена откладывается.
1. Timeweb выдаёт новый IPv4, старый пока остаётся.
2. С homeserv трассой проверяется, что до нового адреса доходят пакеты (трасса идёт дальше третьего узла провайдера).
   Если нет, адрес убирается и берётся следующий, до 6 попыток; если ни один не подошёл, старый адрес остаётся, повтор через 3 минуты.
3. Только после этого старый адрес удаляется, VPS перезагружается, туннель переводится на новый адрес.
4. Ждём **нового** рукопожатия до 150 с (проверка каждые 5 с, выход сразу, как туннель поднялся); если сервер в Timeweb ещё не `on`,
   ещё 120 с один раз. Без рукопожатия делается жёсткая перезагрузка.
5. Ключи рассылаются **один раз** и только после нового рукопожатия и ответа через туннель, иначе откладываются
   (`/var/lib/vampn/keys_pending`) и уходят, когда связь появится. Так же откладывается рассылка, если IP сменили вручную в панели Timeweb.

### Лимиты
- Удачные смены: не чаще раза в час и не больше 4 в сутки.
- Неудачная смена (адрес выдан, а туннель не поднялся) в эти лимиты **не считается**: в `rotations` она записывается с пометкой `fail`,
  повтор через 3 минуты. После 3 неудач подряд автосмена останавливается и приходит одно сообщение: значит, дело не в блокировке адреса
  и нужна проверка VPS вручную (консоль в панели Timeweb). Счётчик сбрасывается, когда связь появилась.
- `--force` обходит часовой и суточный лимиты и предел неудач, но не проверку статуса `on`.

## Рассылка ключей: надёжно и с проверкой

Письмо с ключом уходит с homeserv через Gmail. Раньше сервер знал только «Gmail принял письмо». Теперь:

- **Повторы.** Сбой сети или временный отказ SMTP: ещё две попытки через 5 и 20 с. Неверный пароль или адрес, который почта отвергла, не повторяются (бесполезно).
- **Журнал по каждому человеку:** `/var/lib/vampn/mail-status.tsv` (время, имя, адрес, вид, `ok` или `fail`, причина). `ok` значит «почтовый сервер принял письмо»; дойдёт ли оно до ящика, он не сообщает.
- **`vampn mailstatus`** показывает последнюю отправку по каждому из `users.conf` и причину отказа. Код выхода 1, пока у кого-то не ушло.
- **Сторож сам повторяет неушедшее:** не раньше чем через 10 минут после неудачи, одно письмо за проверку, не больше 3 раз на человека. О новых неушедших пишет в Telegram один раз; если и после 3 повторов не ушло, сообщает ещё раз и сдаётся (нужно проверить адрес или пароль почты).
- **`vampn resendall`** отправляет текущий ключ всем из `users.conf`, неушедшим даёт второй проход через 60 с, в конце печатает `ИТОГ: принято N из M` и при неудачах пишет в Telegram. Письма собираются из копии данных на homeserv, поэтому не зависят от того, отвечает ли VPS. Отказывается работать, если адрес в копии не совпал с адресом туннеля (чтобы не разослать ключи с неверным IP) и в аварийном режиме.
- **Приложение.** `vampn link ИМЯ` и `vampn keyconf ИМЯ` берут данные из той же копии (если она совпадает с туннелем, иначе `link` спрашивает VPS). API приложения отдаёт ключ-токен `vpn://` и `.conf`, из которого приложение строит QR на устройстве. Админ в приложении может нажать «ключ всем заново» и «кому ушло» (это `resendall` и `mailstatus`).

## Ячейки, кабинеты Timeweb и `vampn spawn`
**Ячейка** - отдельный VPN-сервер со своими ключами, IP и туннелем, до 1000 клиентов (`CELL_LIMIT`). Если IP ячейки заблокирован, новые ключи нужны только её клиентам. Ячейка 1 - прежняя система без изменений; ячейки N>=2 живут рядом:
- `VAMPN_CELL=N vampn ...` запускает любую команду homeserv для ячейки N (`status`, `rotate`, `users`, `mirror`, `resendall`...). Сторож ячейки - `vampn-cell@N.timer`.
- **Все ячейки с одного места (homeserv, без `VAMPN_CELL`).** `vampn list` печатает пользователей всех ячеек: имя, **ячейка**, IP, почта, последнее подключение (ячейки опрашиваются параллельно; не ответившая ячейка показана по `users.conf` с пометкой «ячейка не отвечает», неготовая - «не активна»). `vampn reissue|resend|link|keyconf ИМЯ` сами находят ячейку пользователя (по `users.conf`, для заведённых прямо на сервере - перебором ячеек). `vampn users`, `mirror`, `resendall` выполняются для каждой готовой ячейки по очереди, `mailstatus` показывает всех с номером ячейки. С `VAMPN_CELL=N` команда работает только с ячейкой N, как раньше. `vampn peers`, `status`, `server` остаются по одной ячейке.
- **`vampn mailkey N`** - если `vampn resend`/`reissue` на сервере ячейки N пишет `relay failed ... Permission denied`: берёт почтовый ключ сервера (`/root/.ssh/mailrelay.pub`), прописывает его на homeserv (старую строку этой ячейки заменяет, соседние не трогает) и проверяет вход с сервера. `adopt`/`spawn` делают это сами.
- Настройки: `/etc/vampn/cells/N.env` (имя, сеть, лимит, кабинет, id сервера, IP, состояние) и `N.timeweb.env` (токен и id сервера для смены IP). Состояние: `/var/lib/vampn/cells/N`. Туннель: интерфейс `vampnN`, сеть `10.77.(4*(N-1)).0/22` (ячейка 2 - `10.77.4.0/22`, 3 - `10.77.8.0/22`, ячейка 1 - прежняя `10.77.0.0/22`; сервер `.1`, homeserv `.3`), клиенты `/22` (около 1000).
- В `users.conf` необязательный третий столбец - номер ячейки пользователя (нет столбца - ячейка 1). Каждый сервер получает только своих.
- **`vampn cells`** - таблица ячеек: номер, имя, IP, пользователи/лимит, рукопожатие, состояние.
- **`vampn account add ИМЯ`** (токен Timeweb читается со stdin, в выводе его нет, перед сохранением проверяется запросом к Timeweb), `account list|default|del`. Кабинет `main` - тот, что в `timeweb.env`.
- **`vampn spawn [КАБИНЕТ]`** (только админ, ходит по сети в Timeweb и тратит деньги): выбирает самый дешёвый тариф локации `nl-1` (Амстердам) и Debian 13 (если нет - 12), арендует сервер с именем `vampn_N`, ждёт IP, кладёт на него `install.sh` по ssh, поднимает туннель, ключ почты, сторожа ячейки и отправляет пользователей. При сбое пишет в Telegram, ячейку помечает «ошибка», сервер не удаляет (чтобы не потерять деньги и разобраться). Одновременно идёт только один spawn. Ход: `vampn spawnstatus`.
- **`vampn init`** (на новом чистом Debian 13, под root, из клона репозитория: `git clone https://github.com/ahilespelid/vampn && bash vampn/server/vampn/vampn init`): ставит пакеты, AmneziaWG и утилиты `awg`, поднимает файрвол, ssh и самолечение и создаёт рабочую ячейку без homeserv (сеть `--net`, по умолчанию 10.77.4). В конце печатает конфиг, QR и ссылку первого пользователя `client1` и кладёт на сервер открытый ключ homeserv (`homeserv.pub`). Пользователей на таком сервере заводят `vampn add ИМЯ`, убирают `vampn del ИМЯ`. `vampn init --packages-only` - только пакеты.
- **`vampn adopt IP [--hours Ч] [--no-rescue]`** (на homeserv): подключает сервер, поднятый `vampn init`, как ячейку (номер берётся из его сети: 10.77.4 - ячейка 2, 10.77.8 - ячейка 3...), ставит ключи homeserv, туннель, ключ почты и сторожа, после чего переносит в неё **всех отвалившихся из всех ячеек** (нет рукопожатия дольше Ч часов, по умолчанию 1; ни разу не подключались; ячейка не отвечает) и рассылает им новые ключи. Сервер не удаляется и не пересоздаётся; неудачную попытку можно повторить той же командой. **`vampn rescue N [--hours Ч] [--dry]`** - только перенос в существующую ячейку N (`--dry` показывает, кого перенесёт). Перед переносом `users.conf` копируется в `users.conf.bak.ДАТА`.
- **`vampn celldel N --yes`** убирает ячейку и просит Timeweb удалить сервер; отказывает, если в ячейке есть пользователи (без `--force`), и для ячейки 1.
- **`install.sh`** - бандл для чистого Debian: AmneziaWG (DKMS и утилиты), ключи, nft (ssh только из туннеля), sysctl, юниты сервера. `vampn installscript` его печатает; он встроен в `vampn` командой `bash embed.sh` (тест сверяет совпадение). `--render-only --root DIR` пишет файлы без установки.

## Тесты
`bash test.sh vampn` проверяет подбор адреса, порядок удаления и рассылки, пороги 2, 3 и 5 минут, ожидание 150 с, продление при статусе не `on`,
неудачные смены и их предел, автовключение аварийного канала, отложенную рассылку, разбор трассы и живую проверку туннеля, а также `resendall`, журнал и повторы рассылки, сторожа почты,
повторы SMTP в Python-части и ссылку/`.conf` из копии данных, ячейки, кабинеты, выбор тарифа и весь ход `spawn` со сбоями, `install.sh` в режиме `--render-only`, на заглушках (в Timeweb, в туннель и в настоящую почту не ходит). Сейчас 294 проверки.
