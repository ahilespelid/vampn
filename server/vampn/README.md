# vampn (сторож и управление VPN)

Один скрипт `vampn`, который на homeserv лежит в `/usr/local/sbin/vampn`; сторож запускается таймером systemd раз в минуту (`vampn check`).
Здесь хранится его копия. Скрипт с ролями (homeserv, VPN-сервер, аварийный Бостон) определяет роль по конфигам AmneziaWG.

## Как сторож решает, что туннель мёртв
Связь есть, если рукопожатие моложе 45 с **или** sshd VPS отвечает через туннель (TCP 22 на 10.77.0.1 через интерфейс `vampn`;
на VPS этот порт открыт файрволом только для `awg0`). Раньше ждали 300 с без рукопожатия.

| минут без связи | действие |
|---|---|
| 2 | перезагрузка VPS через API Timeweb (не чаще раза в 30 мин) |
| 5 | смена IPv4 (не чаще раза в час и 4 в сутки) |

## Смена IP (`vampn rotate [--force]`)
1. Timeweb выдаёт новый IPv4, старый пока остаётся.
2. С homeserv трассой проверяется, что до нового адреса доходят пакеты (трасса идёт дальше третьего узла провайдера).
   Если нет, адрес убирается и берётся следующий, до 6 попыток; если ни один не подошёл, старый адрес остаётся, повтор через 10 минут.
3. Только после этого старый адрес удаляется, VPS перезагружается, туннель переводится на новый адрес.
4. Ключи рассылаются **один раз** и только после **нового** рукопожатия и ответа через туннель. Если туннель не поднялся,
   ключи откладываются (`/var/lib/vampn/keys_pending`) и уходят, когда связь появится.
Так же откладывается рассылка, если IP сменили вручную в панели Timeweb.

## Письма с ключами и приложение
Все письма с ключами (смена IP, перевыпуск, новый пользователь, повторная отправка, аварийный ключ) проходят через `deliver()` или
`vampn mail` (ретрансляция с VPN-сервера) на homeserv. После отправки письма `notify_app()` пишет в базу `vampn` строку в `keys` и
уведомление в `notifications` (контейнер `vampn_percona`, отметка «письмо ушло» ставится сразу). Приложение с открытым потоком SSE
получает его через несколько секунд. Повторное письмо после смены IP (`dup`) уведомления не создаёт. Пользователям с `active=0` уведомление не заводится.
Если базы или docker нет (например, на VPN-сервере), хук молча пропускается: письмо уже ушло. Виды уведомлений: «Новый ключ VPN: сменился
адрес сервера», «Новый ключ VPN» (перевыпуск), «Аварийный ключ VPN», «Ключ VPN отправлен на почту» (первая отправка или повтор).

## Тесты
`bash test.sh vampn` проверяет подбор адреса, порядок удаления и рассылки, пороги 2 и 5 минут, отложенную рассылку,
разбор трассы и живую проверку туннеля на заглушках (в Timeweb и в туннель не ходит).
`python3 test_mail_hook.py` проверяет хук уведомлений на заглушках (код берётся из самого скрипта; почта и база не нужны).
